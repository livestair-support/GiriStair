# 0.5の機能改修

対象はSwiftUIのiPhone版。LiveStairの全画面をデザインと操作の基準とし、LiveStair本体は変更しません。Androidは既存Flutterを維持し、今回の新しい機能はiPhone向けです。アイコンは最新の1254×1254の提供原本へ両OSとも更新します。

## ユーザー確認済みの判断

- 形式は生大喜利／ネット大喜利（長考）／ネット大喜利（短考）／ハイブリッドの4種別だけを独立して集計します。
- 「興味あり」は参加・戦績の集計から除外。参加を選んだ記録は、日程に応じて参加予定／参加中／参加済を自動表示します。
- 大会で通過した後は段階追加を促します。直前の期間・時刻を引き継いだ下書きを提示し、ユーザーがそのまま保存、または編集して保存します。未保存の日程は自動登録しません。

## 全般と登録

- 起動時の結果入力案内は初回だけ。既読は再起動をまたいで保存します。ネット大会の詳細では、投票が終了した回ごとに入力を1度案内します。
- LiveStairのフォーカス時サジェストを使い、読み仮名・前方一致・最大5件・選択で閉じる仕様を維持します。主催は主催回数を優先します。
- 主催者は左にラベルを残し、右揃えで入力。参加者の人数と貼り付け／OCRは見出し行へ配置。ネット大会の通常参加者欄は表示しません。
- チーム戦は自分のチームから入力。固定人数は人数分の空欄を用意し、無制限は追加方式。ブロックは「ブロック」、振り返りは「メモ」とします。
- 長考の通常は継続サイト。短考は単発の開催日・時刻を基本とし、長考の7日＋7日期間を強制しません。ハイブリッドは開催時刻とネット期間を扱えます。

## 日程と結果

- 段階と同じ段階の1回目・2回目を区別し、旧お題回IDを維持します。投稿参加・投票義務の内部値を残し、編集トグルは表示しません。
- 次の段階／同じ段階の追加は直前の実際の投稿期間・投票期間・間隔・時刻を引き継ぎます。
- 段階の通過／敗退、個人・チーム順位、得点・投票人数・得票率、最終結果、他の入賞者を別記録にします。複数回答は回答ごとの結果と総合個人順位を分けます。
- 通常サイトは所属の有無を選択。各回に当時の所属・順位・結果を保存し、次回の所属を更新しても過去の履歴を変更しません。

## 一覧・詳細・戦績・思考

- 一覧では形式を上、参加中・参加予定／参加済を下に配置。検索項目を形式に合わせ、参加者は検索付きプルダウンで複数選択。カレンダーは形式の色と記号、サイト名、投稿／投票を表示します。
- 詳細の削除は上部メニュー。ネット参加状況は自動表示。お題と回答は思考へリンクし、同じデータを詳細に二重表示しません。
- 戦績は4形式で絞り、結果記入済／結果未入力を分けます。未入力は終了した参加大会のみ。未入力カードは直接結果編集を開きます。
- 思考は回答モードを既定にし、お題モードは別の作成画面。関連する形式→会・日程を選び、生は当日を優先、ネットは進行中を優先し、その他の記録も選べます。
- お題カードは新しい順に並び、投稿／投票期間と終了後の順位・得票率を表示。他人の回答はチェックと回答者、提出回答は複数選択。画像と没案も保持します。

## 保存と検証

schemaVersion1、既存のkind・statusのraw値、Documents/giristair.json、原本退避と原子的保存を維持します。追加項目がない旧JSONも読み込みます。旧回答文字列は読込時に書き換えず、編集後は構造化回答と互換用文字列を保存します。回答を全削除した後に旧本文から復活させません。

Pythonの生成・ブランドテスト、実際のSwiftモデルのデータ互換性・保存・日程・参加状態・回答結果の回帰テスト、Mac CIのiOSアプリビルドを行います。実機のサジェスト・シート・タブ遷移・画像選択・ホーム画面のアイコンと、署名付きTestFlight配信は別途端末で確認します。自動撮影は毎回の必須工程にしません。
