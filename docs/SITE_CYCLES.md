# 通常サイトの周期・リーグ・シーズン（0.6〜0.9）

iPhoneのSwiftUI版を対象とします。4形式は生大喜利／ネット大喜利（長考）／ネット大喜利（短考）／スプシ系。旧hybridのJSON値は維持します。タブ名は「お題/回答」です。

## 登録と現在の状態（0.9のかんたん設定）

登録で入れるのは「今の状態（投稿中／投票中）」「その締切」「次のお題」「投稿期間・投票期間」だけです。投稿締切＝投票開始、投票締切＝結果発表として扱い、次の回からは自動で進めます。サイトから日程や結果を自動取得する機能ではありません。特定のサイト名やサイト固有の仕組み（ブロック内の判定など）を前提にしません。

「次のお題」は4つから選び、保存は従来の `recurrence`／`pattern`／`intervalDays` です。

| 選択肢 | 保存 | 例（投稿7日・投票3日） |
| --- | --- | --- |
| 投票開始と同時 | weekly・overlapping・間隔＝投稿日数 | 毎週お題が出て、前の回の投票と並行 |
| 投票が終わってから | weekly・alternating・間隔＝投稿＋投票 | 投稿→投票→次のお題 |
| 決まった間隔 | weekly・overlapping・間隔＝指定日数 | 2週ごとなど |
| 決まっていない | irregular | 締切が過ぎたら一覧のカードから次の回の締切を入れる |

決まっていないサイトの次の回は、投稿締切（必要なら投票締切）を1つ入れるだけで「第n回」を追加します（`specialPeriods` の regular）。

### 次のお題待ち（0.11）

シーズンの合間などで、投稿中でも投票中でもない時は「今の状態」で「次のお題待ち」を選びます。次のお題の開始が分かれば入れ、その日時から自動で進めます（`notBefore` より前の通常回は作りません）。分からない間は `waitingForNext` で通常回を作らず（特別週は出します）、前の決まりは今の回より前で止めます（新しい決まりとして保存し、過去の回の日程は残します）。一覧のカードは「次のお題を待っています」と出し、「次のお題の締切を入れる」で投稿締切と回の番号（記録した回の続きを候補にする）を入れて再開します。シーズンがあるサイトは「次のシーズンを始める」も出します。どちらの値も古いJSONにはなく、ない時は「待っていない」として読みます。

重なるときは、今回の投稿と前回の投票を別に表示します。単純な今週／来週カードへまとめません。回答を始める操作でその回への参加を確定し、監視用に日程を表示しただけでは参加回数へ数えません。

## 見送り・休止・通知（0.9）

- 投稿中の回は「参加する／今回は見送る」。見送りは `siteSkipped`（参加しない記録）として残し、サイト詳細の履歴に「見送り」と出します。参加回数・戦績・結果入力・通知の対象外です。見送った回は「やっぱり参加する」で参加にできます。
- 投票中の行は参加した回だけに出します。終わった回は「終わった回の結果を記録」から入れ、「この回は結果を記録しない」で案内を止められます。結果の画面でブロックを回ごとに変更でき、「次の回からもこのブロック」でサイトの初期値も変えます。
- サイト詳細の「ほかの操作」→「しばらく休む」で `isPaused`。一覧のカード・通知・新しい回の自動作成を止め、一覧の下に「休止中のサイト n件／再開」を出します。サイトの日程・リーグ・履歴は変えません。再開はサイト詳細のバナーか「ほかの操作」から。
- 通知：まだ決めていない回は「新しいお題が出た時」と「投稿締切の前」。参加した回は従来どおり投稿締切・投票締切の前。見送った回と休止中のサイトは通知しません。

重なるときは、今回の投稿と前回の投票を別に表示します。単純な今週／来週カードへまとめません。回答を始める操作でその回への参加を確定し、監視用に日程を表示しただけでは参加回数へ数えません。

## シーズンと特殊週

シーズンは「第○シーズン」の番号（`seasonNumber`）で持ち、名前は番号から作ります（番号のない旧データは名前の数字から次の番号を読みます）。現在のお題番号と、分かる場合だけ1シーズンの回数（最後のお題番号）を設定します。最後の回の投票が終わると、一覧のカードに「次のシーズンを始める」を出し、最初の回の投稿締切を入れるだけで番号を1つ進め、第1回から始めます（1シーズンの回数・投稿／投票日数は引き継ぎ、特別週は新しいシーズンでは空にします）。シーズンの日数を必須にせず、今のルールで開始日を逆算しません。ルール変更はその回から先へ反映し、以前のルールの投票期間は保持します。最後のお題番号を設定した場合、その後に架空の通常回を生成しません。

最後の半週、エキシビション、プレーオフ、入れ替え戦などは、独立した投稿・投票日時を持つ日程として追加・編集します。同じ特別戦で複数の投稿がある場合も複数の日程を保存できます。通常の7日＋7日へ強制しません。次のシーズンへ切り替えても、参加済みの回のシーズン・リーグ・回答は保持します。次シーズンの特殊日程は前シーズンのIDを使い回さず、新しく確認して追加します。

## リーグと結果

リーグがないサイトも使えます。ある場合は上位から下位の順に名称を登録し、自分のリーグを選びます。

結果入力では順位・メモに加え、昇格／降格の確定と、プレーオフ／入れ替え戦への出場を別々に記録します。出場資格だけでリーグを動かしません。昇降格の確定時は順序から次のリーグを補い、ユーザーが確認・変更して保存します。

所属変更の適用日を記録し、シーズン単位ならシーズン終了後などの指定日から反映します。日付が来る前に現在のリーグを変更しません。既に参加した回の所属を、後からサイトの設定や次回の結果で上書きしません。規定投稿数・得票率・入れ替え戦の判定式はサイトごとに異なるため、自動判定しません。

## お題/回答と一覧

回答モードは長考／その他を切り替えます。長考は投稿中のお題を上に、検索できる履歴を下に表示。その他では自分の回答／他人の回答、回答者、関連する会を保存し、ユーザーの操作でXの投稿作成画面やOS共有を開けます。自動投稿はしません。お題作成モードと画像・使用状態・自由メモも保持します。

一覧・戦績は同じ4形式タブを使い、デフォルト設定から順序を変更できます。戦績の期間条件は「年」を明示します。

サポートは非リンクの準備中表示です。はじめにガイドと仮の長文プライバシー画面は削除し、バージョンを最下部に置きます。

## 保存と確認

既存のschemaVersion1、原本退避、原子的保存、旧日程キーと画像・本文を維持します。未設定の旧サイトに日程の意味を推測して表示せず、設定を促すか保存済みの実日程を表示します。

周期・重複期間・シーズン上限・特殊日程・リーグ適用日・過去の所属・旧JSON・並び順をSwiftで検証し、iOSアプリ全体をMac CIでビルドします。実機の細かな表示・操作とTestFlight配信は別途確認が必要です。反復撮影は必須工程にしません。

## 0.7の合計成績

「シーズンの合計成績を記録」を有効にすると、自分が提出済みにした回答数、得票率の記録がある件数、各回答の得票率の算術平均を表示します。投票人数による加重平均ではありません。他人の回答・未参加の回・不明な率は除外します。旧データの回別成績を使う場合は別件数で表示し、回答別の率と重複させません。

名称を変えても同じシーズンIDなら集計は継続し、次のシーズンには別IDを付けます。シーズン名だけでルールや日数を推測しません。

## 0.14の休みの回・過去の回

サイト側の都合で休みになった回は、カードの投稿中の行の「…」から「運営の都合で休み」にします（`SiteCycleSettings.breakStarts`。休みがない時はキーを書かず、以前のJSONの形を保ちます）。休みの回は作らず、後ろの通常回の番号を1つずつ詰め、「1シーズン○回」の最後の回もその分後ろへずらします。まだ何も書いていない休みの回の記録は消し、参加済み・メモのある回はキャンセルにして、取り消すと戻します。参加した後の回も「今回は投稿しない」で見送りにできます。新しいシーズンでは休みを引き継ぎません。

過去に参加した回はサイト詳細の参加履歴の「参加した回を追加」から、投稿の締切（と回・シーズン・リーグ）で追加します。日程はその回の記録として残し、サイトの日程の設定は変えません。同じ日程の回が参加履歴にある時は追加しません。リーグ・プレーオフ・入れ替え戦などがある複雑なサイトだけ、違うシーズンの回で「今のシーズンとルールが同じか」を聞き、シーズン明けの「次のシーズンを始める」で「ルールの変更」を聞きます（変更ありなら保存後に設定を開きます）。シーズンIDやルールの内容は推測しません。
